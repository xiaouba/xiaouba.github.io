Doom Emacs 博客发布手册

小藕霸霸的烂笔头 · WSL Ubuntu + Hugo + Doom Emacs + Git

仓库 ~/xiaouba.github.io（WSL: Ubuntu-E） 主分支 main 站点 https://xiaouba.github.io/ 更新于 2026-08-11

前提条件（已在 WSL 里配好）

  • Hugo Extended v0.164.0 装在 ~/.local/bin/hugo，已在 PATH 里。
  • 仓库在 ~/xiaouba.github.io，origin 用 SSH，gh auth status 已登录，push 不需要再输密码。
  • publish.sh 已是可执行文件，中文文件名的校验 bug 已修好。
  • :term vterm 已启用并实测编译可用；config.el 加了新的 leader key 绑定（见下方）。

Leader Key 速查

Doom 默认的 emacs-state leader 是 M-SPC，但它在 Windows Terminal 里会被系统窗口菜单吞掉——三种场景，三种按法，记住这张表就够了。

正文 / Magit / Dired
C-c SPC

这些 buffer 都是 evil emacs state，config.el 里已把 leader 从 M-SPC 改绑到这里。

vterm · 输入命令
直接打字

insert state 下按键原样转发给 shell，不经过 leader；打不出字先看是不是掉进了 normal state（按 i 切回来）。

vterm · 收起 / 跳去别处
Esc→SPC …

先退到 normal state，普通 SPC 就是 leader（从没被 Windows 拦截）——o t 收起终端，g g 直接跳进 Magit，不用先关终端。不要用 C-c SPC（C-c 会变成 Ctrl-C 中断信号）。

顺带两件跟这套流程有关的配置事实

  • 不用切 Vim 模式：evil-default-state 设成了 emacs， 正文编辑跟普通 Emacs 一样直接打字。
  • Magit 用原生 Emacs 单键：magit-*-mode / git-commit-mode 被强制设回 emacs state（"use native Emacs keys, not Vim"）——第 6 步的 s / c c / C-c C-c / P p 就是这套，不是 evil 键位。
  1. 01

    新建文章

    从 archetypes/posts.md 模板生成新文章，自动写入 draft: true 的前言，文件落在 content/posts/文章名.md。

    Doom

    C-c SPC p p 切到项目 → C-c SPC o t 弹出终端，跑完命令按上方 "vterm · 收起" 的方式关掉，再用 C-c SPC f f 打开刚生成的文件。

    vterm
    # 中文文件名可直接使用
hugo new posts/文章名.md
  2. 02

    撰写正文

    打开文件后 markdown-mode 自动启用，直接打字。先补全前言字段，再写正文； 发布前必须把 draft 从 true 改成 false，否则 publish.sh 会在第 4 步直接拒绝。

    front matter
    ---
title: "文章标题"
date: 2026-08-10T10:00:00+08:00
draft: false          # 发布前必须改为 false
author: "小藕霸霸"
categories: []
tags: []
description: ""
---
    Doom

    C-x C-s 保存；C-c SPC f f 找其他文件。

  3. 03

    本地预览

    在 vterm 里启动带草稿的本地服务器，浏览器打开 http://localhost:1313， 内容改动自动热重载。+vterm/toggle 只是显示/隐藏，服务器进程会一直在 后台跑，不用每次重启——写文章时收起，想看日志再叫出来。

    vterm
    hugo server -D
  4. 04

    发布前校验

    只检查、不构建，确认前言合规（校验规则见下方清单）。不写 --file 时会 自动挑当前改动的文章。

    vterm
    ./publish.sh --check --file "content/posts/文章名.md"
  5. 05

    校验 + 本地构建

    去掉 --check，校验通过后额外跑一次 hugo --gc --minify 生产构建，确认没有报错再进入下一步。

    vterm
    ./publish.sh --file "content/posts/文章名.md"
  6. 06

    用 Magit 提交并推送

    publish.sh 不会自动 add / commit / push，这一步手动用 Magit 完成——不用先退出上一步的 vterm，直接从终端跳过去就行。

    Doom · Magit

    还停在第 5 步的 vterm 里：Esc 切到 normal state，直接 SPC g g（不带 C-c）打开状态面板——实测过，不需要先收起终端。

    如果已经回到正文等 emacs-state buffer：用 C-c SPC g g。

    光标停在改动文件上按 s 暂存（文件列表标题上按 s 可整体暂存）。

    c c 写提交信息（如 publish: 文章标题），C-c C-c 确认。

    P p 推送到 origin/main。

    等价命令行
    git add content/posts/文章名.md
git commit -m "publish: 文章标题"
git push origin main
  7. 07

    确认自动部署

    推送到 main 触发 .github/workflows/deploy-to-branch.yml： Actions 用 Hugo 构建，再推送到 gh-pages 分支。一两分钟后 https://xiaouba.github.io/ 即可看到更新。

    vterm · 查看进度
    gh run list --workflow deploy-to-branch.yml --limit 1

发布前检查清单

对应 publish.sh 的实际校验规则

  • ✓title 字段非空
  • ✓draft 已由 true 改为 false
  • ✓date 可解析，且不是未来时间
  • ✓校验失败会中止，不会继续构建——按提示定位到具体文件和字段

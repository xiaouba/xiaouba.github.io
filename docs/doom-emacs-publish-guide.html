Doom Emacs 博客发布手册

小藕霸霸的烂笔头 · WSL Ubuntu + Hugo + Doom Emacs + Git

仓库 ~/xiaouba.github.io（WSL: Ubuntu-E） 主分支 main 站点 https://xiaouba.github.io/ 更新于 2026-08-10

前提条件（已在 WSL 里配好）

  • Hugo Extended v0.164.0 装在 ~/.local/bin/hugo，已在 PATH 里。
  • 仓库在 ~/xiaouba.github.io，origin 用 SSH（git@github.com:...），gh auth status 已登录 xiaouba，push 不需要再输密码。
  • publish.sh 已是可执行文件，且中文文件名的校验 bug 已修好。
  • :term vterm 已在 init.el 里启用、跑过 doom sync，原生模块也实测编译并验证可用，整个流程可以不离开 Emacs。
  • config.el 里给 evil-emacs-state-map 加了 C-c SPC → leader 的绑定，替代在 Windows Terminal 里不可用的 M-SPC，实测验证过。

你的 Doom 配置里跟这套流程有关的几件事

  • 不用切 Vim 模式：你在 config.el 里把 evil-default-state 设成了 emacs（注释写着"Key Configuration as Vanilla Emacs"），所以正文编辑跟普通 Emacs 一样直接打字，不需要管 normal/insert。
  • Magit 用的是原生 Emacs 单键：你特意把 magit-*-mode / git-commit-mode 强制设回 emacs state， 注释里写明"use native Emacs keys (s/c/P/F…), not Vim"——下面第 6 步的键位就是这套。
  • :term vterm 现在是开着的：之前 init.el 里 eshell / shell / term / vterm 全被注释掉，编辑和跑命令要分到两个窗口。现在已经把 vterm 取消注释、 doom sync 过，也实测编译了原生模块 — 下面的新建 / 预览 / 校验 / 构建都可以直接在弹出终端里跑，不用再切到 Emacs 外面。
  • leader key 是 C-c SPC，不是 SPC 也不是 M-SPC： 因为你的 buffer 基本都在 evil emacs state（前面这条），Doom 默认的 emacs-state leader 是 M-SPC（Alt+Space）——但实测 M-SPC 在 Windows Terminal 里会 直接弹出系统窗口菜单（跟你 config.el 注释里描述的一样），根本到不了 Emacs。已经在 config.el 里给 evil-emacs-state-map 加了一条 C-c SPC → doom-leader-map 的绑定，实测过能正常触发 +vterm/toggle，下面统一用这个。普通 SPC 在正文里还是老老实实插入一个 空格（实测按 SPC o t 会把 "ot" 原样打进文章）；dashboard 那个 SPC 补丁没动，只在 dashboard 这一个 buffer 里生效，跟正文编辑无关。
  • vterm 里面 C-c SPC 不管用：vterm 在 insert state 下几乎所有按键 都是原样转发给终端的，不经过 Emacs 的按键分发——实测在 vterm 里按 C-c SPC o t 想收起终端，结果 C-c 变成了真正发给 shell 的 Ctrl-C 中断信号，后面的 " o t" 也被当文字敲进了命令行。正确做法：先按 Esc 把 vterm 切到 evil normal state，这时候用普通 SPC o t（不是 C-c SPC）就能收起终端——normal state 下 Doom 原生的 leader 本来就是 SPC，从来没被 Windows Terminal 吃过，只有 emacs state 下的 M-SPC 才有问题。实测验证过。
  1. 01

    新建文章

    在 Emacs 里的 vterm 终端中，从 archetypes/posts.md 模板生成新文章，自动写入 draft: true 的前言，文件落在 content/posts/文章名.md。

    Doom · vterm

    先 C-c SPC p p 切到 xiaouba.github.io 项目， 再 C-c SPC o t 在项目根目录弹出终端。

    打不出字（尤其是 h/j/k/l）？ 说明 vterm buffer 掉进了 evil normal state（通常是不小心按了 Esc 触发的，这是 Doom vterm 的正常设计，用来在终端里滚动/复制）——按 i 切回 insert state 就能继续打字，实测验证过。

    vterm（C-c SPC o t）
    # 中文文件名可直接使用
hugo new posts/文章名.md
    Doom

    命令跑完后先按 Esc（切到 vterm 的 normal state），再按 普通 SPC o t 收起终端 —— 不要在 vterm 里直接按 C-c SPC o t， 那个 C-c 会被当成 Ctrl-C 中断信号发给 shell。 回到正文后用 C-c SPC f f 打开刚生成的文件。

  2. 02

    在 Doom Emacs 中撰写

    打开文件后 markdown-mode 自动启用，直接打字即可（你的配置里这类 buffer 走 emacs state，不是 vim 模态）。先补全前言字段，再写正文； 发布前务必把 draft 从 true 改成 false。

    front matter
    ---
title: "文章标题"
date: 2026-08-10T10:00:00+08:00
draft: false          # 发布前必须改为 false
author: "小藕霸霸"
categories: []
tags: []
description: ""
---
    Doom

    C-x C-s 保存；C-c SPC f f 找其他文件； 记住 leader 是 C-c SPC，不是普通 SPC（会插入空格） 也不是 M-SPC（被 Windows Terminal 系统菜单吞掉），两个都实测验证过。

  3. 03

    本地预览

    在同一个 vterm 里启动带草稿的本地服务器，浏览器打开 http://localhost:1313，内容改动会自动热重载。

    vterm（C-c SPC o t）
    hugo server -D
    Doom · vterm

    +vterm/toggle 是切换显示/隐藏，不是新开一个——服务器会 一直在后台跑，同一个进程不用每次重启。但触发方式因你所在的位置而不同：

    · 在正文 buffer 里（还没打开终端）：C-c SPC o t 弹出。

    · 已经在 vterm 里、想收起它：先 Esc 切到 normal state，再按普通 SPC o t（不带 C-c，否则会把 Ctrl-C 发给 正在跑的 hugo server）。

    需要在当前窗口而不是弹出式小窗打开终端，同样按位置分别用 C-c SPC o T 或 SPC o T（大写）。

  4. 04

    发布前校验

    只做检查、不构建，快速确认 title / date / draft 三项是否合规（不写 --file 时会自动挑当前改动的文章）。

    vterm（C-c SPC o t）
    ./publish.sh --check --file "content/posts/文章名.md"
  5. 05

    校验并本地构建

    去掉 --check，通过校验后会额外跑一次 hugo --gc --minify 生产构建，确认没有报错。

    vterm（C-c SPC o t）
    ./publish.sh --file "content/posts/文章名.md"
  6. 06

    用 Magit 提交并推送

    publish.sh 不会自动 add / commit / push，这一步在 Emacs 里用 Magit 完成——因为 Magit buffer 是 emacs state， 下面全是它的原生按键，不是 evil 的。

    Doom · Magit

    C-c SPC g g 打开 Magit 状态面板。

    光标停在 Unstaged changes 下的文件上按 s 暂存 （整体暂存所有改动可以在文件列表标题上按 s）。

    c c 打开提交信息 buffer，写 publish: 文章标题， C-c C-c 确认提交。

    P p 推送到 origin/main（首次没有上游分支会提示确认）。

    等价的命令行写法
    git status
git add content/posts/文章名.md
git commit -m "publish: 文章标题"
git push origin main
  7. 07

    确认自动部署

    推送到 main 会触发 .github/workflows/deploy-to-branch.yml： Actions 里用 Hugo 构建，再推送到 gh-pages 分支。一两分钟后 https://xiaouba.github.io/ 即可看到更新。

    vterm（C-c SPC o t）· 用 gh 看进度
    gh run list --workflow deploy-to-branch.yml --limit 1

发布前检查清单

对应 publish.sh 的实际校验规则

  • ✓title 字段非空
  • ✓draft 已由 true 改为 false
  • ✓date 可解析，且不是未来时间
  • ✓校验失败会中止，不会继续构建 —— 按提示信息定位到具体文件和字段
